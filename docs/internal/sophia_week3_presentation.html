The submodule trap

Symptom: First push succeeded. But on GitHub, agent-starter-react/ and sophia-glasses/client-sdk-unity/ appeared as EMPTY folders with no source code.

What happened

Both folders were originally cloned from upstream repos, so each had its own .git/ directory inside. When we ran git add at the outer project root, git noticed the inner .git and recorded only a gitlink — a 40-character commit SHA pointing into a separate repo — instead of staging the actual files.

git ls-tree HEAD agent-starter-react
# 160000 commit cee4acfd969c71b836d8421e22110d98b187b01c  agent-starter-react
#   ↑ mode 160000 = submodule gitlink, NOT a real directory

Fix

# 1. Strip the inner .git histories
rm -rf agent-starter-react/.git
rm -rf sophia-glasses/client-sdk-unity/.git

# 2. Tell outer repo to forget the gitlink entries
git rm --cached agent-starter-react
git rm --cached sophia-glasses/client-sdk-unity

# 3. Re-stage everything inside as regular files
git add agent-starter-react/
git add sophia-glasses/client-sdk-unity/

# 4. Verify LFS catches binaries, then commit + push

Destructive in the sense that you lose the inner subproject's git history, but working-tree files are preserved including local edits. Captured in git_setup.md "Gotchas" appendix so we don't repeat.

Three pre deploy code changes

Making the code production safe before deploying anywhere. All three dev safe defaults preserve local behavior when env vars are unset.

1. Auth on token-mint

Was: zero auth. Anyone reaching /token could mint a JWT for any room.

Now: optional X-API-Key header gated by SOPHIA_TOKEN_API_KEY env var. Also added SOPHIA_CORS_ORIGINS for prod CORS narrowing.

sophia-agent/src/token_mint.py

2. Env-driven inference URLs

Was: hardcoded http://localhost:8080 for Whisper, :18080 for Qwen, etc.

Now: WHISPER_URL, QWEN3_URL, KOKORO_URL, SOPHIA_RAG_URL env vars with localhost defaults preserved.

sophia-agent/src/agent.py

3. Split Dockerfile

Was: one Dockerfile bundling everything (agent worker + token-mint).

Now: separate Dockerfile.token-mint that skips Silero/turn-detector download. Smaller image, faster to build + ship.

sophia-agent/Dockerfile.token-mint

Pattern: any prod-only behavior is opt-in via env var. Set the env var to enable; unset = old dev behavior.

The cross-region twist

Discovery: EKS cluster spatial-ai-staging lives in us-west-2. Our shared EC2 is in us-east-1. Different regions = different VPCs by definition.

Confirmed empirically: nslookup whisper-inference.multi-agent.svc.cluster.local from the EC2 returns SERVFAIL. No same-VPC path. Original plan (use cluster.local DNS) was impossible.

Port Forwarding

kubectl port forward FROM the EC2

Same pattern your Mac uses. Works cross-region via EKS public/private API endpoint. Zero infra change.

Deployment problems + fixes

13 distinct problems hit during deployment (full list in mvp_deployment_shared_ec2.md). The four biggest below.

P5. AWS credentials (kubectl AccessDenied)

EC2's IAM Instance Profile sophiaspatialai-ai-gpu-ec2 lacks eks:DescribeCluster. aws eks update-kubeconfig fails.

Fix:

Export YOUR temporary STS credentials as env vars on the EC2. kubectl now uses YOUR user identity (already in cluster's aws-auth). Expires ~1h — re-export per session.

P6. Agent-worker timeout connecting to SFU

agent-worker logs ConnectionTimeoutError: ws://3.227.63.49:7880/agent. Public IP routing through SG (closed) → timeout. Agent + SFU are on the SAME host.

Fix:

Override LIVEKIT_URL=ws://localhost:7880 for the agent-worker container only via docker-compose environment block. network_mode: host makes localhost loop back to the SFU on the same host. Instant.

P7. Turn-detector model not found

RuntimeError: Could not find file "model_q8.onnx". Dockerfile downloads model to /root/.cache/huggingface/ in build stage; multi-stage COPY --from=build /app /app drops the cache.

Fix:

Set ENV HF_HOME=/app/.cache/huggingface in Dockerfile BEFORE the download-files step. Cache now lives under /app and gets copied to the final stage.

P10. AWS Security Group blocks external access

From laptop, curl http://3.227.63.49:7880 times out. From EC2 itself, curl http://127.0.0.1:7880 works. AWS SG = default-deny firewall at EC2's network edge.

Fix:

Add 5 Terraform ingress blocks (TCP 3000/7880/7881/8001 + UDP 50000-60000) to aws_security_group.gpu. PR opened against AIPartnersUSA/aws-infra repo. Currently waiting on infra to merge + run terraform apply.

AWS Security Groups the firewall layer

Layer 1: Services on the EC2

  • SFU listens on 0.0.0.0:7880
  • token-mint listens on 0.0.0.0:8001
  • Frontend listens on 0.0.0.0:3000
  • Anyone INSIDE the EC2 can curl them

Layer 2: AWS Security Group

  • Virtual firewall at EC2's network interface
  • Default DENY all inbound except explicitly listed ports
  • Today: 22 (SSH) + 8888 (Jupyter) only
  • Drops external packets to other ports BEFORE they reach the OS

Our PR to aws-infra

ingress {
  description = "Sophia voice agent frontend"
  from_port   = 3000
  to_port     = 3000
  protocol    = "tcp"
  cidr_blocks = var.allowed_cidrs
}

# + 4 more ingress blocks for 7880, 7881, 8001, UDP 50000-60000
# Follows the var.allowed_cidrs pattern used by JupyterLab + TensorBoard

5 new ingress blocks. Single-file change to environments/single_g5x2large_us_east_1/main.tf in the AIPartnersUSA/aws-infra repo. Once merged + terraform apply runs, external access works.
