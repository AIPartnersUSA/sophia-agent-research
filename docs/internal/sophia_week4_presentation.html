Integration problems + fixes

Four sharp edges hit during integration. All four documented as Q&A in project_complete_doubts.md for future maintenance.

Q28. Google.Protobuf duplicate DLL (ARCore vs LiveKit)

Both com.google.ar.core.arfoundation.extensions and the LiveKit SDK ship their own Google.Protobuf.dll. After adding LiveKit, ARCore Extensions Editor scripts failed with CS0234: 'Protobuf' does not exist in namespace 'Google'.

Fix:

removed the unused ARCore Extensions package + Samples. AR functionality lives in AR Foundation + ARCore plugin directly — Extensions was vestigial.

Q29. Seven LiveKit SDK v1.3.7 API mismatches

Training-data API assumptions didn't match v1.3.7. Examples: RoomOptions namespace ambiguity (LiveKit vs LiveKit.Proto); ConnectInstruction inherits CustomYieldInstruction, NOT awaitable as Task; DataPublishOptions removed in favor of named topic: param; TextStreamReader.ReadAllAsync renamed to ReadAll() returning ReadAllInstruction.

Fix:

Compile-driven discovery · wrote AwaitYield helper that polls IsDone via Task.Yield() · used global::LiveKit.* to disambiguate · all 7 mismatches catalogued with corrected snippets.

Q30. The three-enum dispatch chain (silent OpenAI fallback)

Selected "LiveKit" in dropdown but our [DEBUG_0604_LiveKit] logs never fired. Investigation: ProviderConfig has FOUR layers between dropdown and runtime — UI enum, ScriptableObject bundle override, runtime enum, AND a converter switch with a silent _ => OpenAI default.

Fix:

Added LiveKit to layers 1 + 4, cleared the customizedEndpointsBundle in the asset to bypass layer 2. Hidden default arms are a teaching moment — always trace dispatch end-to-end.

Q31. Unity 6 HTTP block

System.InvalidOperationException: Insecure connection not allowed at FetchTokenAsync line 353. Unity 6 blocks HTTP by default; our token endpoint is plain HTTP on EC2 MVP.

Fix:

Player Settings → Other Settings → Configuration → Allow downloads over HTTP → "Always allowed" (insecureHttpOption: 2). Reverts naturally when Phase 2 moves backend to HTTPS.
